# ADR 0001 — M0 stack choices and approved additions

Status: accepted (2026-10-16, product owner)

## Choices among the section 3 options
- ORM: **Drizzle** (SQL migrations committed in `packages/db/migrations`).
- Auth: **Auth.js** for the magic-link flow, with our own session layer (ADR 0002).
- Jobs: **pg-boss**. Errors: **Cloud Error Reporting** (no Sentry, no `SENTRY_DSN`).
- Email: **Postmark** (Mailpit locally).
- Monorepo: **pnpm workspaces** (no Turborepo).

## Approved additions (R10)
- Libraries: `@node-rs/argon2` (passwords), `otplib` + `qrcode` (TOTP), `@aws-sdk/client-s3` +
  `@aws-sdk/s3-request-presigner` (MinIO), `@google-cloud/storage`, `@google-cloud/kms`,
  `google-auth-library` (ID tokens to call `clamav`), `pino`. Build tooling: `tsx`, `esbuild`.
- Tables/columns: `session`, `verification_token`, `invitation`, `mfa_recovery_code`,
  `rate_limit`, `firm.wrapped_data_key`, `app_user.mfa_enabled_at`.
- `MIGRATE_DATABASE_URL` secret (owner role) next to `DATABASE_URL` (runtime role) — RLS needs a
  non-owner runtime role.
- Our own ClamAV HTTP wrapper image (`infra/images/clamav`).

## Interpretations made while building (flagged for review)
- `user` is reserved in Postgres → table `app_user`.
- `membership.consultant_id` is a nullable column with no FK or CHECK until the `consultant`
  table exists (M1). Consultants can be invited in M0 without a consultant record.
- Section 12 has no row for generic uploads. M0 uses `UPLOAD_FILES` (all roles) and
  `VIEW_ALL_FILES` (Admin/Manager/Finance); consultants see only their own uploads.
- "Managers also act as Finance" is supported by `can(..., { managersActAsFinance })`, but there
  is no firm setting for it yet (open decision 2).
- Sign-up says when an email already has an account (409). Email verification is not in M0.
- Sessions last 12 hours (no sliding expiry). TOTP codes aren't yet replay-protected within
  their 30-second window — hardening item for M8.
- `sa-clamav` (no data access) is used for the `clamav` service instead of the default compute
  account; it isn't in the 24.4 table.

## M1 additions (approved 2026-10-17)
- `firm_holiday` table for the holiday calendar (13.3 item 1).
- The seed creates Summit Factoring as a FACTOR party only; its factoring profile arrives with M5.
- Seed users share a dev password (`SEED_PASSWORD`, default `lonestar-dev-password`); the seed prints
  authenticator keys for admin@ and finance@ and refuses to run in staging or production.

## M1 interpretations (flagged for review)
- `membership.disabled_at` and `membership.mfa_required` were added for "disable" and "require MFA"
  on Users and roles (13.3 item 2). Disable is per firm: `app_user.status` is global, and one
  firm's Admin must not lock a user out of another firm.
- Consultant invitations now require a consultant record (`invitation.consultant_id`), and the
  section 5.1 rule "consultant_id required when role = CONSULTANT" is a CHECK (NOT VALID, so older
  rows are left alone).
- Activating an engagement requires a REGULAR bill rate covering its start date (otherwise
  `resolveRate` returns NO_RATE and invoicing would be blocked from day one).
- Rates are changed by ending the current rate and adding a new one (section 16 `addRate`/`endRate`);
  an end date can only move earlier, so a later rate can never be overlapped by an edit.
- Party `kind` can't change after creation. Employment type can't change once a consultant has
  engagements.
- `party.code` is 2–10 capital letters or digits; required for prime vendors and implementation
  partners (they can be bill-to and feed `{CLIENT}`).
- Unknown `{TOKENS}` in a numbering pattern are literal text, as section 7.4 says.
- Document status flags "expiring" within 30 days of expiry.
- Invoice cycle ≥ timesheet cycle uses the order WEEKLY < BIWEEKLY < SEMIMONTHLY < MONTHLY.
- Same-firm composite foreign keys back up tenant isolation for every cross-table reference.

## M2 additions (approved 2026-10-17)
- Libraries: `sharp` (image sizes, normalizing, the image hash), `heic-convert` (HEIC → JPEG), and
  `pdfjs-dist` with `@napi-rs/canvas` (PDF pages rendered to images, max 10, as 8.1 says). Gemini is
  called through `@google/genai` in Vertex mode with the worker's service account. The default
  model is `gemini-2.5-flash` (open decision 7), set by `VERTEX_MODEL`.
- Inbound email: Postmark's JSON inbound webhook. Postmark doesn't sign inbound posts, so the URL
  carries HTTP basic auth: `postmark:<POSTMARK_INBOUND_WEBHOOK_SECRET>`. The secret is generated by
  Terraform and compared in constant time. The JSON payload is stored as the raw message.
- `firm.timesheet_auto_reply` (default on) is the section 9 "auto-reply (configurable)" setting.
- Fixtures (8.7): 35 synthetic VMS screenshots (Fieldglass-, Beeline- and calendar-style, approval
  emails, phone photos, low-res, crops, PDFs) until pilot firms provide real ones (open decision 8).
- DUPLICATE_EVIDENCE (7.6): an image within 5 bits of another timesheet's file only counts when the
  content also matches: the same VMS timesheet ID, or the same name, period and total. Same-VMS
  screenshots of different weeks hash 0–1 bits apart, so the image hash alone would block most
  timesheets. The sha256 rule is unchanged.

## M2 interpretations (flagged for review)
- Columns beyond 5.4, needed by the screens: `evidence.inbound_email_id` (the unmatched queue shows
  the email), `evidence.consultant_id` (sender matched, timesheet not yet), and
  `inbound_email.status_reason` (why an email was rejected or left unmatched).
- Message-ID de-duplication is per (firm, inbox), so one email addressed to two firms reaches both.
- `timesheet_check` keeps one row per code. A re-run keeps a resolution when the message is
  unchanged and reopens the check when it changes. Checks that no longer apply are deleted. Each
  re-run is audited (`checks_run`).
- A SUBMITTED timesheet waits while an extraction is QUEUED or RUNNING, then moves on with
  `checks_pass` or `checks_fail`. A FAILED extraction counts as EXTRACTION_PENDING (BLOCK),
  routing the timesheet to manual review.
- NEEDS_REVIEW → VERIFIED happens automatically only when no blocking check is left at all.
  When a person has resolved blocks, a person presses Verify.
- `save_entries` on a DRAFT keeps it DRAFT. That is the editor's own save; 6.1 lists only
  NOT_STARTED and RETURNED.
- Returning a timesheet clears earlier check resolutions; the resubmission is reviewed afresh.
- An INVOICED timesheet, its entries and its evidence are locked by a trigger as well as by the
  handlers (R4, T13).
- Pre-fill (8.6 step 4) applies to the email, bulk-upload and unmatched-assignment paths only. A
  consultant's own upload is compared, not copied into their entries. When there is no daily
  breakdown, a total up to 24 hours goes on the last working day. A larger total is spread evenly
  over the working days, because a day can't exceed 24 hours (5.4).
- Matching (8.6) uses the extracted period, or the span of the daily dates when the header isn't
  visible. With no period at all, a consultant's only ACTIVE engagement is used.
- Consultants never see bill amounts or other consultants' names in checks: PO_EXCEEDED and
  RATE_CHANGE_IN_PERIOD are hidden from them, and NO_RATE and DUPLICATE_EVIDENCE get plain messages.
- PO_EXCEEDED counts invoiced amounts. Invoices arrive in M3, so until then only the timesheet's
  own bill amount is compared with the PO.
- Section 14's 01:00 and 09:00 firm-time jobs run hourly and act on firms whose local hour has
  passed the target. Both are idempotent (unique periods; one reminder per timesheet per day,
  at most 5).
- Activating an engagement creates its started-period timesheets immediately; the nightly job
  covers new periods after that.
- Job processors live in `apps/web/src/server/jobs`, next to the handlers they share, and the worker
  entry is `apps/web/src/worker.ts`. `packages/jobs` holds the job names, payloads, schedules and
  the pg-boss runtime. Native and proto-file packages stay outside the worker bundle and are
  installed next to it in the image.
- AI usage: the first read that reaches the model is billable (pages = rendered pages). Retries
  after validation failures, provider or system errors, duplicates (same sha256, no second read)
  and virus-scan rejections are recorded as not billable, with the 22.4 reason. Provider cost is
  stored in cents on the extraction. The exact millionths of a dollar are kept in `raw_json`.
- Vendor invoice and remittance extraction are part of the Extractor interface but throw until M4/M5.
  The AP inbox stores email without processing it until vendor bills exist (M4).
- Finance can remove a screenshot only while the timesheet is editable (`removeEvidence`), so a
  wrong upload can be fixed before submitting.
